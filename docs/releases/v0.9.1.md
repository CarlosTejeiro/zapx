## ZAPX 0.9.1 — Linux CPU fix

A focused patch for high CPU usage on Linux.

### 🐛 Fixed

- **WebKitWebProcess pinned near 100% CPU on Linux** — on many NVIDIA systems
  (especially under Wayland) WebKitGTK's DMABUF renderer spins the web process
  in a busy repaint loop, so the webview burns a full CPU core even when
  nothing is happening. ZAPX now disables that renderer at startup on Linux
  (`WEBKIT_DISABLE_DMABUF_RENDERER=1`, only when you haven't set it yourself),
  which lets the webview idle normally. Fixes the AppImage loop and lowers CPU
  on every Linux build.

### 🔧 Changed (Linux)

- **Opaque window** — window transparency is off on Linux now (still on for
  macOS vibrancy / Windows acrylic). No visual change — the app already fills
  the window opaquely with square corners — it just removes the per-frame alpha
  compositing WebKitGTK was doing for nothing.
- **Static cursor glow** — the Phosphor/Amber glow themes no longer animate the
  cursor's blur filter on an infinite loop; the glow is static, so it looks the
  same at rest without the continuous repaint.

### ℹ️ Building on Arch

If compiling from source failed with missing dependencies, use the PKGBUILD in
`packaging/arch/` — `makepkg -si` installs the required build deps (webkit2gtk,
gtk3, …) for you.

### ⚠️ macOS: "ZAPX is damaged and can't be opened"

The macOS bundles are not signed/notarized. After dragging the app to
Applications, run `xattr -cr /Applications/ZAPX.app` — or right-click →
**Open** on first launch.
